# M5 跟弹考核设计（v0.5.0）

> 状态：设计稿，待 M4 完成后实现。对应 issue #26–#29。
> 目标：用手机麦克风判断「音对不对、拍子稳不稳」，给出可解释的双维度评分，并把结果送回 M4 计划引擎。

## 1. 范围

**做**

- 单音旋律/单音 Riff 的跟弹判定（一次只发一个音）。
- 音准分：每个音与参考音高的偏差（音分）。
- 节奏分：每个音相对节拍格点的 onset 偏差（毫秒）。
- 结果页：逐音标记、错误位置回标 TAB、示范/自己录音 A/B 对比。
- 结果写入 `attempt`，驱动次日计划。

**不做（1.0 前）**

- 和弦/扫弦/闷音的自动评分（先只记录不判）。
- 推弦、滑音、泛音的精确判定（v1 遇到这些技巧标注为「不判」，只要求起音对）。
- 多声部、双音、复调。
- 实时逐音反馈（先录完整段再评分，避免 UI 与音频线程耦合）。

## 2. 数据流

```
参考乐句 (Phrase)
   │ 取单音声部/指定小节区间
   ▼
参考事件序列 ref[(tick, midi, string, fret)]
   │
手机麦克风 ──► AudioRecord 16bit/48k ──► 分帧 RMS + MPM 音高
   │                                       │
   │                                       ▼
   │                              音符切分（onset + 稳定段）
   │                                       │
   └──────────────► 对齐（DTW）◄───────────┘
                           │
                           ▼
              逐音音准/节奏偏差 → 双维度评分
                           │
                           ▼
              结果页 + 写入 attempt + 计划引擎
```

## 3. 采集与音符切分

- 复用 `MicrophoneCapture`（`UNPROCESSED` 优先）与 `MpmPitchDetector` + `PitchTracker`。
- 帧长 2048（42.7 ms），hop 512（10.7 ms）；每帧输出 `(rms, frequency, clarity)`。
- **onset**：RMS 从「低于自适应噪声底 × 2」跃升到「高于 × 3」，且持续 ≥3 帧；两次 onset 最小间隔 60 ms。
  - 噪声底用前 0.5 s 的 RMS 中位数估计；之后用指数滑动平均更新（只在静音段更新）。
- **稳定段**：onset 后连续 ≥3 帧 clarity ≥0.75，取中位频率作为一个音；段尾由下一次 onset 或静音 80 ms 截断。
- 音高转为 MIDI 浮点：`69 + 12*log2(f/440)`；与参考音比较时用音分差。
- 录音同时落盘为 48 kHz/16-bit 单声道 WAV，供结果页回放；默认保留最近 10 次，超出自动删。

## 4. 对齐

参考事件按 tick 排序，转成「以第一拍为 0」的秒数（按当日速度）。检测音序列按时间排序。

用 **DTW** 对齐，允许：
- 匹配：一个检测音对一个参考音；
- 漏弹（参考音没有对应检测音）：删除惩罚；
- 多弹（检测音没有对应参考音）：插入惩罚。

代价：

```
cost(match) = |midiDetected - midiRef| * 1.0
            + |onsetDetected - onsetRef| * 0.5   // 秒
cost(skipRef) = 3.0
cost(extra)   = 2.0
```

对齐后用**中位时间偏移**做整体延迟补偿：先算所有匹配对的 `onsetDetected - onsetRef` 中位数，再重新计算节奏偏差。这样「整体晚 100 ms 但很稳」不会毁掉节奏分（人本来就会跟得稍晚），而「忽快忽慢」会被扣分。

## 5. 评分

### 5.1 音准

- 每个匹配音：`cents = 1200*log2(fDetected/fRef)`。
- 命中：|cents| ≤ 50（半音内）；弯音/滑音标记的音只判起音，不计入音准分母。
- 音准分 = 命中数 / 应弹数 × 100；漏弹按 0 分计入。
- 额外输出：平均绝对音分偏差（仅统计命中音）。

### 5.2 节奏

- 每个匹配音：`deviationMs = onsetDetected - onsetRef - medianOffset`。
- 命中：|deviation| ≤ 80 ms（约 1/8 拍 @ 90 BPM）。
- 节奏分 = 命中数 / 应弹数 × 100。
- 额外输出：平均绝对偏差、最大偏差、偏早/偏晚倾向。

### 5.3 综合与判定

- 综合分 = `0.5*音准 + 0.5*节奏`（可配置）。
- 通过线：综合 ≥80 且音准 ≥80 且节奏 ≥75。
- 结果分四档：优秀（≥90）/ 通过（≥80）/ 再练（60–79）/ 不熟（<60）。
- 写入 `attempt.score_accuracy` / `score_rhythm`；M4 引擎用综合分替代自评。

## 6. 结果页

- 顶部：综合分、音准分、节奏分、四档结论。
- 逐音条：横向等距排列参考音，颜色表示命中/音准偏差/节奏偏差/漏弹；点击看「应弹 E4 / 实际 F4 +80 音分 / 晚 120 ms」。
- TAB 小节条：复用 M3 的 `TabBarCard`，错误音用红色描边。
- 回放：示范（合成音轨）与自己的录音切换/连续播放；录音音量归一化。
- 底部按钮：再练一次（回到播放器，速度不变）、完成（写记录、回今日）。

## 7. 与 M4 的接口

```kotlin
data class AssessmentResult(
    val phraseId: String,
    val bpm: Double,
    val accuracyScore: Double,
    val rhythmScore: Double,
    val passed: Boolean,
    val noteResults: List<NoteResult>,
    val recordedWavPath: String?,
)
```

M4 的考核步骤拿到 `AssessmentResult` 后：
- `passed` → 走 M4 的通过分支（连续通过计数 +1）；
- 未通过 → 失败分支（降速 10%）；
- 用户仍可手动改判（「我觉得这次还行」），但会标记 `manualOverride=true`。

## 8. 测试

**纯算法（`:core:assessment`）**

- 用 M3 的 Karplus-Strong 合成参考旋律，按目标时间加 0/±50/±150 ms 偏移，检测器应还原。
- 加入白噪、整体延迟 120 ms、漏一个音、多弹一个音，DTW 对齐与分数符合预期。
- 音准偏差 ±10/49/51 音分的边界。
- 节奏偏差 ±79/81 ms 的边界。
- 空录音、全程静音、全程噪声：返回 0 分且不崩。

**真机**

- 内置《晨光》旋律：正常弹、故意慢半拍、故意按错品、漏弹，各录 3 次。
- 与人工听感对比：通过/不通过结论一致率 ≥80%。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 手机麦克风拾取音箱外放，示范音被当成自己弹的 | 考核时先播放示范，静音 1 秒后再开始采集；或要求戴耳机 |
| 房间噪声导致 onset 误检 | 自适应噪声底 + 最小间隔 + 最短稳定段 |
| 低音弦泛音导致音高跳八度 | 复用 M2 的 MPM 抗泛音参数；考核前用调音器确认 |
| 用户整体延迟（跟得晚） | 中位偏移补偿；只惩罚相对波动 |
| 电吉他失真导致音高检测不稳 | 先要求 CLEAN 通道考核；失真下的判定后续再调 |
| 录音体积 | 只保留最近 10 次；单次 1 分钟约 5.8 MB |

## 10. 实施顺序

1. `:core:assessment`：音符切分 + DTW + 评分 + 合成信号单测（#26）。
2. 录音落盘与回放（#28）。
3. 结果页与 TAB 错误标记（#27）。
4. 接入 M4 考核步骤，替换自评（#29）。
5. 真机对比调参（通过线、容差）。
