# guitar-dojo 开发任务目标（ROADMAP）

> 本文档是整个项目的开发任务总纲：愿景、已定决策、里程碑与 issue 拆分。
> 每个里程碑 = 一个可安装的版本 = 一批 issue。原则：**一个功能完整走一圈**（issue → 开发 → CI 绿 → tag + CHANGELOG），不攒一大批一起发。
> 仓库远端名 `guitar-dojo`，本地目录名为 `Guitar-Tools`（历史原因，不强求一致）。

## 1. 愿景与目标用户

给「想坚持练琴但缺乏自律与路径」的电吉他初学者（就是我）的安卓日常训练 App。核心不是工具箱，而是**每日训练流**：打开 App → 调音 → 设备调试 → 今日乐句练习 → 考核 → 保养收尾，一条流走完算一天。

用户画像与现状（决定难度曲线）：

- 电吉他初学者：单音旋律 ≤100 BPM，不会和弦/推弦/揉弦；保留指起手难弹响，速度 60 BPM 四分音符以下；左右手交互对不上轨，节奏感差。
- 手型条件：手掌肥大、手指短小（教学内容里的手型建议需考虑此因素，不照搬"标准手型"教条）。
- 练琴时间：平时住校无琴（在校日只能做无琴内容），周末节假日+寒暑假为琴上训练日。
- 教材痛点：市面教程「帅帅」类太浅，《365日电吉他手的养成计划》第二周就啃不动——本项目难度曲线取两者之间，且允许随时降级重练。

## 2. 已定决策（2026-10-24 立项确认）

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 线上仓库名 | `guitar-dojo`（App 中文名「吉他道场」） | 每日打卡、按流程修行的隐喻；GitHub 无直接撞名；FretFlow 因撞名排除 |
| 技术栈 | Kotlin + Jetpack Compose（Material 3），minSdk 26 | 音频密集型 App 需要低延迟音频（AAudio/Oboe）与成熟 DSP 生态；Compose 动画能力强，满足"现代设计审美+过渡动画"要求 |
| 训练计划引擎 | 纯算法规则引擎 | 考核不过→降速/次日重练，通过→提速/进阶；离线可用、行为可预期、零成本。预留引擎接口，1.0 后实验性接 LLM |
| 无琴日内容 | 纳入 v1：乐理微卡片 + 节奏拍手训练 | 在校日也有打卡闭环，习惯不断；乐理以每天一张卡片+一道小题的形式融入，绑定当日乐句，不排大块时间 |

## 4. 里程碑与 issue 拆分

> issue 标题前缀即 Conventional Commits 类型。每个 issue 开工时按 dev-workflow 规范补全：背景、实现规划、验收标准；完成后写小结再关闭。
> 下列 `#1`–`#35` 已于 2026-10-24 在 GitHub 建好（编号与本文件一致），并按里程碑挂了 milestone 与标签。开工时在 issue 内补过程记录，关闭前写小结。

### M0 工程骨架（v0.0.x）

- #1 `feat: Android 工程初始化` — Gradle + Kotlin 2.x + Compose BOM + Material 3，minSdk 26；模块 `:app` + `:core:audio`（音频引擎独立模块便于单测）。验收：`gradlew assembleDebug` 通过。
- #2 `feat: 导航与主题骨架` — 底部导航四页：今日 / 工具（节拍器·调音器入口）/ 乐句库 / 我的；主题与过渡动画基调。验收：模拟器运行可见四页切换。
- #3 `chore: ktlint + detekt 接入` — 风格问题交给工具。验收：`gradlew lint check` 通过。
- #4 `chore: CI 流水线` — GitHub Actions `ci.yml`（PR / push main 触发构建+lint+测试，≤10 分钟）；`release.yml` 占位（tag 触发）。验收：首跑全绿。
- #5 `docs: README 构建说明补全` — 怎么构建、怎么装进手机、CI 徽章。

### M1 节拍器（v0.1.0）

- #6 `feat: 节拍器音频调度引擎` — `:core:audio` 内实现：基于 AAudio/Oboe 音频时钟（timestamp）调度采样播放，**禁止用 Handler/postDelayed 系统时钟**；强弱拍音色、每拍细分音色。验收：引擎层单元测试（调度时刻序列 vs 理论值）。
- #7 `feat: 节拍器 UI` — BPM 1-300（拖动+输入+±按钮）、拍号（每小节拍数 1–12）、每拍细分（1/2/3/4）、tap tempo、小节内循环进度显示（四拍圈点高亮等）。验收：功能全可用。
- #8 `test: 长跑漂移测量与调优` — 设计可重复的漂移测量方案（如录屏/录音对比节拍间隔），记录数据与调参过程到 issue。验收：30 分钟长跑累积误差听感不可辨。
- #9 `feat: 后台播放` — 前台服务 + 通知栏控制。验收：锁屏/切后台节奏不中断不漂移。
- #10 `polish: 节拍器动效` — BPM 摆锤/脉冲动画、页面过渡，符合整体设计基调。

### M2 调音器 + 拾音器（v0.2.0）

- #11 `feat: 音高检测引擎选型与实现` — Kotlin 实现 YIN 或 MPM（选型对比记录进 issue；可参考 TarsosDSP 的 MPM 实现与 PitchKit 的吉他调参）。验收：合成正弦/方波信号（E2–E6 全音域）检测结果正确，单元测试覆盖。
- #12 `feat: 抗泛音与稳定性策略` — 针对电吉他泛音丰富、现有调音器误判的问题：倍频/基频八度误差抑制、置信度门限、中值平滑、最低能量门限。验收：真机对音箱外放单音测试，误判率主观上低于现用 Play 调音器（记录对比案例进 issue）。
- #13 `feat: 调音器 UI` — 吉他模式（6 弦目标音 EADGBE，逐弦引导）+ 半音阶模式（任意音）；指针 + 偏差音分数显示。验收：两种模式可用，视觉反馈清晰。
- #14 `feat: 拾音器模式` — 同引擎的持续音符名/八度/音分显示，供扒谱辅助。验收：长音持续显示稳定不跳。
- #15 `test: 音高检测鲁棒性用例` — 合成信号：标准音、含泛音叠加、加噪、音头瞬态。验收：用例全绿并纳入 CI。

### M3 乐句库 + 变速播放器（v0.3.0）

- #16 `feat(tools): GP→JSON 离线转换器` — `tools/` 下 Python 脚本，参考 MUSE 的 `gpif_parser.py`（GP7/8 解析）与 `guitar_tab.py`（排指）自写；输出乐句 JSON Schema v1（小节/音符/时值/弦品/技巧/速度/拍号）。验收：MUSE/music 下 7 个 GP 谱全部转换成功，字段完整。**注意：转换产物只落 `local_phrases/`，不入库。**
- #17 `feat: 乐句数据模型与内置乐句` — App 内置全部自编内容：爬格子变体若干、C 大调/G 大调音阶、基础 riff、简单单音旋律（无版权）；分级标注（对应我的水平档位）。验收：乐句库页可浏览筛选。
- #18 `feat: TAB 简化渲染` — 滚动小节条：小节网格 + 音符块 + 弦品标注 + 播放高亮；**选小节交互**（点选若干小节循环）。图形化六线谱后置。验收：渲染流畅、小节选取直觉。
- #19 `feat: MIDI 合成变速播放` — SoundFont 吉他音色合成，0.25x–1.5x 任意变速（预设 50%/75%）、选小节循环、与节拍器引擎共用音频时钟同步。验收：变速/循环无缝、无爆音、与节拍器对齐。
- #20 `chore: local_phrases 导入流程` — 版权谱的本地导入方式（adb push 或应用内文件导入）与目录约定文档化。验收：按文档操作后 App 能加载自选乐句。

### M4 每日训练流（v0.4.0）

- #21 `feat: 计划规则引擎` — 每日任务生成（热身 5min → 技术练习 → 今日乐句 → 考核）；每个练习项带掌握度状态机：未达标→降速 10–20% 或次日重练；达标→提速或进阶；连续达标→进入下一档。周末高强度/在校日轻量（只排无琴内容）。验收：给定模拟训练记录，生成的次日计划符合规则（单元测试）。
- #22 `feat: 训练向导流程页` — 「开始今日训练」向导串联：调音检查（进 M2 调音器）→ 设备调试图文卡片 → 今日乐句（讲解 + 手型图 + 变速练习，进 M3 播放器）→ 考核（M5 前先占位自评）→ 保养收尾清单。支持中途退出、断点续练。验收：完整走通一天训练流。
- #23 `feat: 设备调试卡片` — GA15II 面板图文：音量/音色/增益（CLEAN 与 DISTORTION 档）、Epiphone 拾音器拨杆（颈/桥/双）、四旋钮（双音量双音调）位置；不同练习类型的推荐设置。图源见 `docs/画图提示词.md` D 组。验收：卡片内容与真机对照无误。
- #24 `feat: Room 训练记录与打卡日历` — 训练历史（时长/项目/考核成绩）、连续打卡天数、日历视图。验收：记录持久化，重装前可导出（简易 JSON 导出即可）。
- #25 `feat: 保养收尾清单` — 擦弦、归位提醒、（可选）换弦周期提示的图文清单。验收：每日流收尾环节可用。

### M5 考核系统（v0.5.0）

- #26 `feat: 跟弹判定` — 录音 → M2 引擎取音高序列 → 与乐句谱对齐：音准判定（音高匹配容差）+ 节奏判定（onset 对齐节拍格点容差）。单音乐句起步（匹配我当前水平与引擎能力）。验收：对内置单音乐句主观判定可用，错误位置能标出。
- #27 `feat: 评分与结果页` — 音准/节奏双维度评分、错误位置标回 TAB 小节条。验收：结果页一目了然。
- #28 `feat: 录音回放对比` — 示范音轨与自己的录音连续/切换播放。验收：可 A/B 对比收听。
- #29 `feat: 考核结果联动计划` — 成绩写入记录、驱动 #21 引擎调整次日计划。验收：闭环可见（考核差 → 次日计划出现降速重练项）。

### M6 手型图与教学内容（随 M4/M5 并行）

- #30 `docs: 画图提示词清单维护` — `docs/画图提示词.md` 持续补充；用户负责用 DeepSeek 出图，产出入 `app/src/main/assets/`（或后续图集目录）。
- #31 `feat: 图文内容组件` — 手型图 + 要点文案的数据结构与展示组件（关键帧翻页、要点高亮）。验收：M4 向导中手型讲解可用。

### M7 无琴日模式（v1.0 前）

- #32 `feat: 乐理微卡片` — 内容库 v1（20–30 张：音符时值/节拍/音名/音阶结构/级数等基础），每日一张 + 一道小题；卡片尽量绑定当日乐句的乐理点。验收：在校日打开 App 有完整打卡内容。
- #33 `feat: 节奏拍手训练` — 播放目标节奏型 → 屏幕点击或麦克风拍击 → 判定时刻偏差给分；难度从四分音符到切分。复用 M1 调度与 M2 检测。验收：判定反馈准确，能进打卡记录。

### M8 打磨发布（v1.0.0）

- #34 `polish: 全局动效与深色模式` — 统一过渡动画语言、深色主题适配全页面。
- #35 `chore: v1.0.0 发布` — 签名、CHANGELOG、发布检查单（测试全绿→版本号→干净环境验证→回滚方案）、GitHub Release。

## 5. 1.0 后实验性方向（不承诺）

- LLM API 接入：训练计划讲解、基于长期记录的主动调整建议（引擎接口已预留）。
- 图形化六线谱渲染（替代简化小节条）。
- USB/蓝牙音频接口输入（改善拾音质量）。
- 和弦按响判定（考核扩展到和弦）。

## 6. 流程约定（遵循 dev-workflow）

- 分支模型：个人项目**简化主干开发**——平时直接提交 main；实验性/大改动开 feature 分支验证后合回。
- commit：Conventional Commits + 关联 issue 号，如 `feat: 节拍器音频时钟调度引擎 (#6)`。
- issue 即需求池 + 进度板 + 踩坑日志：开工写背景/规划/验收标准，过程记数据与坑，关闭前写小结。
- 版本：SemVer；每个里程碑收尾打 tag + 更新 CHANGELOG。
- 版权红线：`local_phrases/` 永不入库；仓库内置乐句必须自编无版权。
