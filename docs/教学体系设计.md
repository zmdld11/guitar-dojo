## 2. 练习安排：本轮新增证据与结论

训练计划设计.md 的十条原则与引擎规则（+5/−10 BPM、3 训练日掌握、1/3/7/14/30 复习、交错闸门）证据映射仍然成立，**本轮不改引擎**。补充三项该文档没写透的证据，只产生文案与卡片层的小修订：

### 2.1 心理练习——无琴日的替代练琴（初步证据）

- Driskell、Copper 与 Moran 1994 的元分析（后续 2020 年 24 年再评估结论一致）：心理练习对动作表现有显著正效应，弱于身体练习，**认知成分越重的任务收益越大**；Bernardi 等 2013 在钢琴任务中验证心理练习改善准确性与时值预期 [B1][B2][B3]。
- 乐句练习恰好是认知成分重的任务（指法、把位、节拍要同时管）。
- 产品含义：无琴日「心理练习」块从一句话提示升级为引导式——按乐句小节走：每小节先想指法/把位，再在心里「听」一遍；次日琴上日引擎本来就默认考核昨日主练句，天然衔接「昨晚想的 → 今早考的」。新增练法卡 `practice.mental`（已落地，见 §4.5）。

### 2.2 微学习——卡片形式的合法性（初步证据）

- 微学习研究：1–10 分钟、单一概念、高频次的形式在参与度与保留上有正效应（Luo 等 2025）[B4]，与间隔效应结论一致。
- 产品含义：卡片「一卡一事、答案 1–2 句」的方向被支持，不改结构；检索练习（先答后看）强于重读，M7 的「小题」扩展是自然延伸（Roediger 与 Karpicke 2006）[B5]。

### 2.3 伤害预防与休息（较强证据，针对音乐家）

- Chan 与 Ackland 2014 综述：规律休息对演奏相关肌肉骨骼失调（PRMD）有保护作用；Guptill 2010：教师主动安排休息与热身和损伤率下降相关 [B6][B7]。
- 产品含义：`practice.rest` 卡补充「疼感在休息 10–15 分钟后还不消，当天别再练」（已落地）；热身步文案强调「热身是把手活动开，不是练到酸」。

## 3. 指法教学规范（M6 图集与向导文案的依据）

### 3.1 左手：先「腕直、拇指低、压力最小」，再谈「标准手型」

- 拇指的作用是支点与配重，不是捏握。拇指过高越过琴颈上缘会迫使腕屈曲——这是腕管压力的生物力学风险姿势；教学共识是拇指在琴颈后方、大约与中指对齐（教学惯例 + 人体工学共识，直腕是各来源最一致的一条）[B8][B9]。
- 按弦压力：够响即止。「越用力越正确」无证据，且过度用力与 PRMD 相关 [B6]。
- **手型适配（本项目核心用户：手掌肥大、手指短小）**：「每指纵向对一品」的教条没有解剖学依据要求人人如此。允许三个自由度：
  1. 手腕角度微调（以直腕为界，不硬掰）；
  2. 按弦指可微斜——斜按缩短横向跨度，短手指者的常用代偿；
  3. 用把位移动替代强行跨品。
  判据是**发音清楚 + 全身放松**，不是手型像不像教材照片。A1/A2 图的文案要按这个口径写，不写「手指必须垂直指板」一类教条。

### 3.2 保留指：是「省力」不是「纪律」

- 保留指（按住不放）的教学价值：减少移动 = 减少出错机会与疲劳，A4 图的三关键帧就是讲这个。
- 但「永远保留」不是长期规则：旋律进行中无用的保留指会闷掉延音，进阶后按音乐需要抬指。卡片与图注写清楚「现阶段按住省力，以后按音乐需要抬」。

### 3.3 右手：交替拨从手腕来

- 教学惯例层：拨片松握；交替下上；运动来自腕部而不是整条手臂；跨弦的经济拨弦后置到进阶。
- B1（握法）、B2（交替拨三帧）图集成时的文案按「松、小、稳」三个字展开。

### 3.4 教学顺序与三步讲法

- 顺序：左手先单独建立（1-2-3-4 → 反向 → 三连音），右手交替拨在第 2 周跨弦阶段并入——curriculum 现有顺序与此一致，不动。
- 每个技术点的讲法固定三步：**图（关键帧）→ 一句要领 → 常见错误对照**（A2 四格图）。向导热身/主练步的手型提示就按这个模板写。

## 4. 乐理教学设计（易接收）

### 4.1 证据与原则

- **先声后符（sound before symbol）**：Kodály/Orff 系教学法的共同原则；认知负荷理论支持「元素先隔离、再入语境」（Zimmerman 2007；2025 年有 CLT 音乐教学法的直接研究）；实践界的争议点在器乐初学的应用方式——结论不是「不教符号」，而是「先听过，再给符号」[B10][B11][B12]。
- **理论服务正在弹的句子**：绑定当周乐句，不在训练流里插入与练习无关的乐理章节。curriculum 已做一半（每周绑 2 张），v2 补全并加讲解。
- **听辨先行**：音程比较→识别的练习存在迁移（Little 2019）[B13]；「参考歌记忆法」流行但迁移证据弱。App 相对 B站视频的决定性优势：**能直接播**——音程、音阶、E5 都可用引擎合成演示，「点一下就听」比「看动画里的键盘」少一层抽象。
- **检索练习**：先答后看已实现；小题（四选一/品格点选）是 M7 #32 的预留扩展。

### 4.2 乐理卡 v2 模板

```kotlin
// 现有字段
prompt   // 问一件事
answer   // 1–2 句：先结论，再例子
detail   // 补充 / 常见混淆
figure   // 可选插图

// v2 建议扩展（#32，可空，向后兼容）
sound    // 可选：听感示例（内置乐句片段 id 或合成音规格，卡面点播）
quiz     // 可选：一道小题（四选一或在品格上点选）
```

`sound` 是本次设计最重要的一步：把 16 张乐理卡里「能听的」从符号记忆改成听感判断，走 App 内合成，不加资源体积。

## 5. 教学内容的生产管线（B站 AI 乐理视频参考）

### 5.1 B站乐理视频的形式拆解

代表系列（好和弦、西蒙老师、三分钟音乐社、知凡乐学等）的共同点：一集一个概念、3–8 分钟、动画可视化（键盘/谱面高亮随口播走）、节奏快。制作工具链分四类：

| 路线 | 代表工具 | 适用 | 教学事实可靠性 |
| --- | --- | --- | --- |
| 精确动画 | Manim 社区版（Python，2026-11 当前 0.21.0；可免 TeX 用 MathTypst，`add_sound` 配音频） | 数学/乐理这类「对象与变化可代码化」的内容 | 高——内容是代码，可校对、可版本管理 |
| AI 流水线 | Code2Video（NUS showlab：Planner→Coder→Critic 三智能体生成 Manim 教学视频）；极坐标⋅XYZ 等工作区（分镜 JSON→TTS→Manim→mp4） | 批量产出精确讲解动画 | 高（Manim 底座）+ AI 生成效率 |
| 时间线编排 | Remotion / Motion Canvas（TS，按帧编排、旁白同步事件） | 与解说节奏强绑定的信息动画 | 高 |
| 扩散模型文生视频 | Seedance / HappyHorse 等 | 片头、氛围、演示性镜头 | **低——音符、品格数、音程大概率画错，不可用于教学事实** |

### 5.2 本机可用能力（查证于 2026-11-22）

- **已装 skill**：pptx（分镜脚本/讲义）、excalidraw（示意图）、pdf/docx/xlsx。没有已装的视频制作 skill。
- **插件市场可装（均未安装）**：
  - `video-agent-kit`：云端语音转录与合成、抽帧理解、时间线、预览渲染、QC、TTS——适合给 Manim 无声成片配音合成；
  - `video-generation`（Seedance）、`happyhorse-video`、`libtv-cli`：文生视频/视频画布；
  - `ruic-card`：分层画稿 + Blender + Three.js 做 3D 视差闪卡，可出 MP4/微信动图——与训练卡片系统形式契合但工程重；
  - `hyper3d-3d`：3D 模型。
- Manim 本身不依赖任何插件：本机 Python `pip install manim` + ffmpeg 即可渲染。

### 5.3 对本项目的结论

1. **App 内交互可视化优先于视频**。训练流里需要的是「点一下听到 E5 由哪两个音构成」「品格板高亮纯五度」——视频给不了交互，卡片 + 引擎合成天然支持，且不打断训练闭环（微学习口径下，训练中插 10 秒听感优于切出去看 5 分钟视频）。这是 §4.2 `sound` 字段的依据。
2. **视频只做外部内容（可选）**。最小管线：pptx skill 写分镜脚本 → Manim 渲染无声版 → video-agent-kit 配 TTS 合成。产物发 B站或放本地 assets 试听，不进 APK 主包（体积）。
3. **扩散文生视频不用于教学事实**，只可用于片头/氛围。
4. 不预装任何视频插件；需要试点时按 §5.2 逐个装（装插件属于工作区变更，先经确认）。
