# M3 乐句库与变速播放器设计（v0.3.0）

> 状态：设计定稿，开始实现。对应 issue #16–#20。
> 本文只描述 App 侧与离线工具的设计；版权红线见文末。

## 1. 目标与非目标

**目标**

- 内置一批自编乐句，打开即练：爬格子、音阶、基础 riff、单音旋律。
- 把本地 Guitar Pro 谱离线转成 JSON，在手机上加载（只落 `local_phrases/`，不入库）。
- 简化 TAB 小节条：能看清弦/品、能选小节循环、播放时高亮。
- 0.25x–1.5x 变速，音高不变；循环无缝；节拍器拍点与乐句共用一条音频流。

**非目标（1.0 前）**

- 完整六线谱排版（符尾、连音线、装饰音图形）。
- SoundFont/采样音色、力度分层、真实音箱模拟。
- GP5 等旧版二进制格式、反复记号/跳房子（v1 忽略，转换时打印警告）。
- 多轨混音；一个 JSON 只导出一条轨道。

## 2. 总体数据流

```
Guitar Pro .gp (本地, 不入库)
      │  tools/gp2json.py（离线, 仅标准库）
      ▼
phrase JSON (schema v1) ──→ local_phrases/（gitignore）
      │
      ├── adb push 到 Android/data/<pkg>/files/phrases/
      └── 应用内 SAF 选择文件后拷贝到 filesDir/phrases/
                              │
app 内置 assets/phrases/*.json ┘
                              ▼
                    PhraseRepository（合并、去重、排序）
                              ▼
         PhraseLibraryScreen ──→ PhrasePlayerScreen
                              │        │
                              │        ├─ Compose TAB 小节条（Canvas）
                              │        └─ PracticeEngine（:core:audio）
                              │              ├─ LoopPlan（帧级事件）
                              │              ├─ PluckedStringVoice ×N（Karplus-Strong）
                              │              └─ ClickSynth（与节拍器同款）
                              ▼
                        播放脉冲 SharedFlow → 小节/拍高亮
```

## 3. JSON Schema v1

### 3.1 约定

- 时间单位统一用 **tick**，`ppq` 默认 960（一个四分音符 = 960 tick）。不存秒，避免变速时重算浮点。
- `tuning` 按 **6 弦→1 弦（低→高）** 存 MIDI 音高；变调夹用 `capo` 单独表示。
- `midi` 是实际发声音高；`string`/`fret` 只用于显示。两者必须自洽（转换器负责保证）。
- 一个文件一条轨道。文件里再有别的乐器也不导。
- 未知字段忽略，缺省字段按默认值，便于以后加字段不破旧数据。

### 3.2 结构

```json
{
  "schemaVersion": 1,
  "id": "builtin.chromatic.basic",
  "title": "爬格子 · 基础四连音",
  "description": "1-2-3-4 指序，6 弦到 1 弦。",
  "difficulty": 1,
  "tags": ["热身", "爬格子"],
  "origin": "builtin",
  "tuning": [40, 45, 50, 55, 59, 64],
  "capo": 0,
  "ppq": 960,
  "bars": [
    {
      "index": 0,
      "startTick": 0,
      "lengthTicks": 3840,
      "timeSignature": [4, 4],
      "tempoBpm": 80
    }
  ],
  "notes": [
    {
      "bar": 0,
      "tick": 0,
      "durationTicks": 960,
      "midi": 40,
      "string": 6,
      "fret": 0,
      "velocity": 0.8,
      "techniques": ["palm_mute"]
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | int | 目前固定 1 |
| `id` | string | 全局唯一；内置用 `builtin.*`，本地导入用 `local.*`（导入时若冲突自动加后缀） |
| `title` / `description` | string | 展示用；`description` 可空 |
| `difficulty` | int 1–5 | 1=入门，5=接近当前极限 |
| `tags` | string[] | 展示与筛选，建议 1–3 个 |
| `origin` | `builtin` / `local` | 决定列表分组与删除权限 |
| `tuning` | int[4..8] | 低→高，MIDI；默认标准调弦 |
| `capo` | int 0–12 | 变调夹品数 |
| `ppq` | int 96–3840 | 每四分音符 tick 数 |
| `bars[]` | object[] | 必须覆盖全曲，`startTick` 连续；支持每小节变拍号/变速 |
| `notes[]` | object[] | 按 `tick` 升序；`bar` 必须匹配所在小节；`tick` 为全曲绝对位置 |

`techniques` 取值（v1 可显示，暂不影响合成）：

`hammer_on`、`pull_off`、`slide`、`bend`、`vibrato`、`palm_mute`、`harmonic`、`dead_note`、`accent`。

### 3.3 校验规则

加载时逐条校验，失败给出「第几小节/第几个音符 + 原因」，不静默丢弃：

- `schemaVersion == 1`；`ppq` 在范围内；`bars` 非空且首尾相接。
- 每个 `note.tick` 落在某个小节内；`durationTicks > 0`。
- `string` 在 1..`tuning.size`；`fret` 在 0..24；`midi` 在 0..127。
- 由 `tuning[string-1] + capo + fret` 推出的音高与 `midi` 相差 ≤ 0 个半音；不一致视为数据错误（转换器必须先修好再输出）。
- 同一 tick 上同一弦不能有两个不同品的音（物理不可弹）。

内置乐句在 CI 里全部过校验；本地导入失败只影响该文件。

## 4. GP → JSON 转换器（#16）

`tools/gp2json.py`，只依赖标准库（`zipfile` + `xml.etree`），与 MUSE 的 `gpif_parser.py` 同源思路，但输出本项目的 schema。

处理规则：

1. **格式**：支持 GP7/8 `.gp`（ZIP + `Content/score.gpif`）。旧版 `.gp5` 直接报错并提示先另存为 `.gp`。
2. **选轨**：默认选第一条非鼓、弦数 ≥4、有音符的轨道；`--track N` 指定。输出 `trackName`。
3. **音高**：以 `<Midi><Number>` 为准。**不信任**文件里的 `String`/`Fret`：本地样本中部分 Songsterr 导出谱的弦品与音高整体错位。
4. **排指**：若某音的弦品与音高一致则保留；若不一致比例 >10%，整条轨道用 DP 重排：
   - 候选 = `midi - capo - tuning[string]` 在 0..24 内的所有 (弦, 品)。
   - 以「同时发声的音符为一列」（同一 tick，或 onset 差 ≤30 ms），列内同弦互斥、非空弦跨度 ≤4 品。
   - 代价 = 把位中心移动 + 低把位先验 + 空弦奖励 + 同音高同弦延续奖励（与 MUSE `guitar_tab.py` v2 同思路，独立实现）。
   - 转换结束把「弦品与音高不一致的音数」写入报告；App 端再校验一次。
5. **时值**：`Rhythm/NoteValue` + 附点 + 连音（tuplet）→ tick；tie 链合并成一个长音（同弦同品同音高，`origin`→`destination` 连续）。
6. **小节**：按 `MasterBar/Time` 推进 `startTick`；拍号/速度变化写入对应 bar。忽略反复与跳房子，打印警告。
7. **输出**：默认写 `local_phrases/<原文件名>.json`；`--out` 可改。**任何情况下都不写 `app/src/main/assets/`**，脚本里硬编码这条检查。
8. **报告**：轨道、音符数、时长、重排比例、被丢弃的音（超出音域/无法排指）。

验收：本地 7 个 GP 全部转换成功；随机抽查 3 个小节的音高与 JSON 一致；`git status` 不含 `local_phrases/`。

## 5. 内置乐句（#17）

全部自编，生成脚本 `tools/build_builtin_phrases.py` 是唯一事实来源，输出到 `app/src/main/assets/phrases/`。脚本支持 `--check`，CI 校验产物与脚本一致。

## 6. 播放引擎（#19）

放 `:core:audio`，输入 `Phrase`，不依赖 Compose/Context。

### 6.1 时间轴：LoopPlan

速度/循环区间变化时**重建**，而不是改采样率：

```
LoopPlan(
  loopFrames,                 // 一个循环区间的总帧数
  notes: [(startFrame, endFrame, midi, velocity, palmMute)],
  clicks: [(frame, accent)],  // 拍点；可选开关
  barFrames: LongArray,       // 每个小节在循环内的起始帧
  barIndices: IntArray,       // 对应原曲小节号
  beatFrames: LongArray       // 每个拍点（用于 UI 脉冲）
)
```

- `framesPerTick(bar) = sampleRate * 60 / (tempoBpm * ppq) / speed`。
- 变速 = 重建 LoopPlan，保持当前 tick 位置，音高不变。
- 循环 = 只取选中小节的音符；音符起点 rebase 到循环起点；`playhead %= loopFrames` 回绕。
- 音符尾巴跨循环边界时自然延续（合成器 voice 不打断），听感无缝。
- 与节拍器同步：click 事件与音符在同一 `render()` 里混音，共用 AudioTrack 播放头，不存在两条流的启动偏移。

### 6.2 合成：Karplus-Strong

- 每个音一个 `PluckedStringVoice`：噪声激励 + 延迟线 + 两点平均低通 + 一阶全通分数延迟。
- 延迟长度：`D = sampleRate/f - 0.5`（减掉平均滤波的 0.5 采样），整数部分进环形缓冲，小数部分进全通。
- 实测 E2–E6 音准误差 ≤1.2 音分（原型验证）；单元测试用 MPM 检测合成音，断言 ≤5 音分。
- `palm_mute`：缩短衰减、降低高频；`dead_note`：极短噪声。
- 力度只做幅度与亮度微调（v1 不做多层采样）。
- 复音上限 16；新音超出时抢占最旧且最弱的 voice。
- 停止/切歌：5 ms 淡出，避免爆音。

### 6.3 引擎线程

沿用 M1 的「AudioTrack 低延迟 + 播放头轮询」：

- 音频线程按 256 帧渲染，`playhead` 为循环内帧位置。
- 轮询线程每 4 ms 读 `playbackHeadPosition`，越过拍点/小节线时发 `PracticePulse(barIndex, beatInBar)`。
- 采样率 48 kHz，失败回退 44.1 kHz；`underrunCount` 暴露给调试。
- 页面离开即停止（v1 不做后台播放；M4 训练流需要时再抽服务）。

## 7. UI（#18）

### 7.1 乐句库

- 顶部标题 + 筛选 chip：全部 / 热身 / 音阶 / Riff / 旋律；难度用 1–5 点标记。
- 卡片：标题、描述、难度点、标签、时长、BPM。
- 「本地乐句」分组：内置之后显示；空态给「导入 JSON」按钮与 adb 路径提示。
- 导入：SAF `ACTION_OPEN_DOCUMENT`（`application/json`），命名冲突加 `-2` 后缀；导入后立即校验，失败弹具体原因。

### 7.2 播放页

- 顶栏：返回、标题、难度。
- TAB 小节条：横向 `LazyRow`，每个小节 Canvas 画 6 条弦线 + 品位数字块； chords 竖向堆叠；当前小节描边高亮；循环区间底色。
- 小节选择：点第一下设为循环起点，点第二下设为终点（反向自动交换）；再点已选中的小节清除。选区两端显示 `A`/`B`。
- 控制区：播放/停止、速度 chip（0.25 / 0.5 / 0.75 / 1.0 / 1.25 / 1.5）+ 滑杆（0.25–1.5，步长 0.05）、节拍器开关（默认开）。
- 播放时自动滚动到当前小节；退出页面停止播放。
- 速度显示同时给出「基础 BPM × 倍率 = 实际 BPM」。

## 9. 测试与验收

**单元测试（`:core:phrase`）**

- 合法样本解析；缺字段/越界/弦品与音高不一致/同弦冲突的错误信息。
- 内置 JSON 全部通过校验（读取 assets 的测试放 `:app`）。

**单元测试（`:core:audio`）**

- LoopPlan：80 BPM、4/4、960 PPQ 下每拍 36000 帧（48 kHz）；变速倍率与帧数成反比；循环区间只含选中小节；跨边界回绕。
- KS：MPM 检测 E2/A2/D3/G3/B3/E4/E6，误差 ≤5 音分；衰减单调；无 NaN/削波。
- 混音：click 与音符同帧对齐；停止淡出无阶跃。

**工具**

- `gp2json.py` 对 7 个本地 GP 全量跑通（CI 不跑，因谱子不入库）；结果手动抽查。
- `build_builtin_phrases.py --check` 进 CI。

**真机/模拟器**

- 打开内置乐句 → 选 3–5 小节 → 0.5x 播放 → 加速到 1.0x → 音高不变、无爆音、循环无缝。
- 节拍器开关切换时拍点不偏移。
- 导入一个本地 JSON → 出现在列表 → 可播放；删除文件后刷新消失。

## 10. 关键决策与偏差

| 决策 | 结论 | 理由 |
|---|---|---|
| 音色方案 | Karplus-Strong 物理建模，不用 SoundFont | 免 NDK/大体积采样；音准实测 ≤1.2 音分；复音开销低 |
| GP 音高来源 | MIDI 优先，弦品重排 | 本地样本存在弦品与音高错位；保证 TAB 与声音一致 |
| 时间单位 | tick + 每小节 tempo | 变速只重建时间轴，不改采样率，音高不变 |
| 与节拍器同步 | 同一 AudioTrack 内混音 | 两条独立音频流无法保证启动相位一致 |
| 反复记号 | v1 忽略并警告 | 练习场景先按线性铺开；后续在 JSON 里加 `repeat` 结构 |
