# M4 每日训练流设计（v0.4.0）

> 状态：设计稿，待实现。对应 issue #21–#25。
> 目标：把「调音 → 设备调试 → 今日乐句 → 考核 → 收尾」串成一条每天 15–30 分钟、能断点续练的流程，并由纯规则引擎决定今天练什么。

## 1. 设计原则

1. **规则可解释**：每个任务都带一句「为什么是它」（如「昨天 90% 速度通过，今天 +5%」），不做黑盒。
2. **无隐藏副作用**：计划生成只读历史与配置，返回纯数据；写入只发生在用户完成任务时。
3. **一票否决只有调音**：音不准时后续练习没有意义，调音未通过不进入乐句环节（可手动跳过并记录）。
4. **M5 前用替代信号**：考核系统未就绪时，用「自评 + 节拍器达成速度」判定，接口保持与 M5 一致，后续替换评分来源即可。
5. **无琴日不硬凑**：在校日只排乐理微卡片 + 节奏拍手，不生成「假装练琴」的任务。

## 2. 单日流程

| 步骤 | 内容 | 时长（15 分钟档） | 可否跳过 |
|---|---|---|---|
| 1. 调音 | 进 M2 调音器，六弦依次通过（±5 音分） | 2 min | 可跳过（记录「未调音」） |
| 2. 设备调试 | GA15II 面板 + 拾音器拨杆图文卡片；按今日练习类型给推荐设置 | 1 min | 可跳过 |
| 3. 热身 | 已掌握的爬格子/音阶，1.0x，2 小节循环 | 3 min | 不可（可换同档热身） |
| 4. 今日乐句 | 当前课程乐句，按引擎给的速度/小节区间练 | 6 min | 不可 |
| 5. 考核 | 当前乐句在目标速度完整走一遍；M5 前自评 | 2 min | 不可 |
| 6. 收尾 | 保养清单：擦弦、归位、关音箱；勾选完成 | 1 min | 可跳过 |

25/30 分钟档把时间加到第 4 步（多一条复习乐句），不增加步骤。

**断点续练**：每一步完成即落库；中途退出后，「今日训练」卡片显示「继续：第 4 步 · 今日乐句」，点击直接回到该步。

## 3. 计划规则引擎

放 `:core:plan`（纯 Kotlin，无 Android 依赖），输入全部显式传入，单元测试覆盖规则表。

### 3.1 输入

```kotlin
data class TrainingProfile(
    val level: Int = 3,                 // 1-5，与乐句难度同一标尺
    val minutesPerDay: Int = 15,        // 15/25/30
    val noGuitarWeekdays: Set<Int> = emptySet(), // ISO 1=周一
    val allowSkipTuning: Boolean = true,
)

data class PhraseProgress(
    val phraseId: String,
    val currentBpm: Double,
    val targetBpm: Double,
    val consecutivePasses: Int,
    val consecutiveFails: Int,
    val lastPracticedEpochDay: Long,
    val nextReviewEpochDay: Long?,
    val mastery: Mastery,               // LEARNING / CONSOLIDATING / MASTERED
)

data class AttemptRecord(
    val phraseId: String,
    val epochDay: Long,
    val bpm: Double,
    val selfRating: SelfRating,         // EASY / OK / HARD
    val tuningPassed: Boolean,
)

data class PlanInput(
    val todayEpochDay: Long,
    val profile: TrainingProfile,
    val curriculum: Curriculum,
    val progress: Map<String, PhraseProgress>,
    val recentAttempts: List<AttemptRecord>,
)
```

### 3.2 输出

```kotlin
data class DailyPlan(
    val dateEpochDay: Long,
    val kind: DayKind,                  // GUITAR / NO_GUITAR
    val tasks: List<PlanTask>,
    val estimatedMinutes: Int,
)

sealed interface PlanTask {
    val reason: String
    data class Tune(val reason: String) : PlanTask
    data class Setup(val ampPreset: String, val reason: String) : PlanTask
    data class Warmup(val phraseId: String, val bpm: Double, val bars: IntRange?, val reason: String) : PlanTask
    data class Practice(val phraseId: String, val bpm: Double, val bars: IntRange?, val speed: Double, val reason: String) : PlanTask
    data class Assess(val phraseId: String, val targetBpm: Double, val reason: String) : PlanTask
    data class Review(val phraseId: String, val bpm: Double, val reason: String) : PlanTask
    data class TheoryCard(val cardId: String, val reason: String) : PlanTask
    data class ClapRhythm(val patternId: String, val bpm: Double, val reason: String) : PlanTask
    data class Cooldown(val checklistId: String, val reason: String) : PlanTask
}
```

### 3.3 选句规则（按优先级）

1. **继续昨天的未通过项**：`consecutiveFails > 0` 的乐句排在第 4 步，速度降 10%。
2. **到期复习**：`nextReviewEpochDay <= today` 的乐句，取「掌握度越高、间隔越久」的一条，放在第 4 步之后（25/30 分钟档）。
3. **当前课程的新句**：课程单元里第一个 `mastery != MASTERED` 的乐句。
4. **热身**：从 `mastery == MASTERED` 且标签含「热身/爬格子」的乐句中，取最久没练的一条；没有则用课程第一条。
5. **考核**：默认考核当前课程乐句；若今天有新句，考核昨天的主练句（避免「学完立刻考」的错觉）。

### 3.4 掌握度状态机

| 事件 | 条件 | 结果 |
|---|---|---|
| 通过 | 自评 EASY/OK，且达到当日目标速度 | `consecutivePasses + 1`，`consecutiveFails = 0` |
| 连续通过 2 次 | — | 下次目标速度 +5%（不超过乐句 targetBpm 的 110%） |
| 连续通过 4 次 | 且达到 targetBpm | `mastery = MASTERED`，进入间隔复习队列 |
| 未通过 | 自评 HARD，或没达到目标速度 | `consecutiveFails + 1`，下次速度 −10%（不低于 targetBpm 的 50%） |
| 连续未通过 3 次 | — | 换同技术点的替代乐句；没有替代则拆成 2 小节 + 再降 10% |
| 调音未通过 | — | 只记录，不影响乐句进度 |

间隔复习：通过后 `nextReview = today + [1, 3, 7, 14][passes - 1]`；复习未通过则 `nextReview = today + 1`，掌握度降回 CONSOLIDATING。

### 3.5 速度目标

- 乐句 JSON 的 `bars[].tempoBpm` 是「示范/目标速度」；练习速度 = 目标 × 速度倍率。
- 首次练习从 50% 起步；引擎输出的 `bpm` 是实际练习 BPM，`speed` 是相对目标倍率（0.25–1.5）。
- 达到 100% 且连续通过 2 次后，可以把目标速度上调 5%，上限为原目标 ×1.1（避免把练习变成赛跑）。

### 3.6 时间预算

| 档位 | 调音 | 设备 | 热身 | 主练 | 复习 | 考核 | 收尾 |
|---|---|---|---|---|---|---|---|
| 15 min | 2 | 1 | 3 | 6 | — | 2 | 1 |
| 25 min | 2 | 1 | 4 | 10 | 5 | 2 | 1 |
| 30 min | 2 | 1 | 4 | 13 | 7 | 2 | 1 |

预估分钟只是展示值；实际以用户完成各步为准。

## 4. 课程资产

`app/src/main/assets/curriculum.json`，与乐句库解耦：

```json
{
  "schemaVersion": 1,
  "id": "builtin.curriculum.starter",
  "title": "入门 4 周",
  "weeks": [
    {
      "index": 1,
      "focus": "左手独立与 1-2-3-4 指序",
      "phraseIds": ["builtin.chromatic.basic", "builtin.scale.c-major"],
      "targetBpm": 80,
      "theoryCardIds": ["theory.string-names", "theory.beat"]

```

规则引擎只认 `phraseIds`；乐句内容仍由 M3 的乐句库提供。找不到 id 时跳过并给出错误，不崩。

首版课程用现有 8 条乐句排 4 周：

|---|---|---|
| 1 | 左手独立 | 爬格子基础、C 大调音阶 |
| 2 | 反向与跨弦 | 爬格子反向、G 大调音阶 |
| 3 | 三连音与五声 | 爬格子三连音、A 小调五声 |
| 4 | 应用 | E5 Riff、单音旋律 |

## 5. 持久化（Room）

数据库 `guitar-dojo.db`，版本 1。

### 5.1 表

```sql
training_day(
  epoch_day INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,            -- GUITAR / NO_GUITAR
  plan_json TEXT NOT NULL,       -- DailyPlan 序列化快照
  current_step INTEGER NOT NULL,
  completed_steps TEXT NOT NULL, -- JSON array of step ids
  started_at INTEGER,
  finished_at INTEGER
)

phrase_progress(
  phrase_id TEXT PRIMARY KEY,
  current_bpm REAL NOT NULL,
  target_bpm REAL NOT NULL,
  consecutive_passes INTEGER NOT NULL,
  consecutive_fails INTEGER NOT NULL,
  mastery TEXT NOT NULL,
  last_practiced_epoch_day INTEGER,
  next_review_epoch_day INTEGER
)

attempt(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  phrase_id TEXT NOT NULL,
  epoch_day INTEGER NOT NULL,
  bpm REAL NOT NULL,
  self_rating TEXT NOT NULL,
  tuning_passed INTEGER NOT NULL,
  score_accuracy REAL,           -- M5 接入后填
  score_rhythm REAL
)

theory_card_seen(
  card_id TEXT PRIMARY KEY,
  last_seen_epoch_day INTEGER NOT NULL
)
```

- `plan_json` 存快照，保证「今天中途改规则/升级 App」也能续上当天计划。
- M5 接入后只加列/加表，不改现有字段语义。

### 5.2 写入时机

- 生成计划：`training_day` 插入（幂等，同一天重复进入读现有行）。
- 完成一步：更新 `current_step` / `completed_steps`。
- 完成考核：写 `attempt`，更新 `phrase_progress`（规则引擎算出的新状态由调用方写回，引擎本身不写库）。
- 收尾完成：`finished_at`。

## 6. 向导状态机

```
IDLE → TUNE → SETUP → WARMUP → PRACTICE → [REVIEW] → ASSESS → COOLDOWN → DONE
```

- 每步有 `stepId`；`training_day.current_step` 指向下一步。
- 可回退到上一步查看，但不回退进度（避免重复写 attempt）。
- 退出：保留状态；「今日训练」卡片显示继续入口。
- 调音步骤：复用 M2 调音器，但只要求六弦依次 InTune；完成后回向导。跳过时记录 `tuningPassed = false`。
- 设备步骤：图文卡片（M6 的 D 组图）；按任务类型给预设（CLEAN / 轻失真 / 失真）。
- 练习步骤：复用 M3 播放器，预置引擎给出的 BPM 与小节区间；「练完了」按钮进入下一步。
- 考核步骤：先完整播放一遍示范，然后用户跟弹，最后自评（轻松/刚好/吃力）。M5 换成自动评分。
- 收尾：保养清单勾选，完成打卡。

## 8. 测试

**纯规则引擎（`:core:plan`）**

- 给定空历史 → 生成 15 分钟计划，含调音/设备/热身/主练/考核/收尾。
- 昨天 HARD → 今天同一乐句速度 −10%，排在第 4 步。
- 连续 2 次 EASY 且达标 → 目标速度 +5%。
- 连续 4 次通过 → mastery=MASTERED，生成 1 天后复习。
- 复习到期 → 计划里出现 Review 任务。
- 连续 3 次 HARD → 切换替代乐句。
- 在校日 → 只生成 TheoryCard + ClapRhythm，不出现 Tune/Practice。
- 缺失乐句 id → 跳过该任务，计划仍可生成。
- 同一天重复调用 → 返回同一份计划（幂等）。

**Room**

- 计划快照读写、步骤断点续练、attempt 写入后 progress 更新、重装前导出 JSON。

**UI / 模拟器**

- 完整走通 15 分钟档（可跳过调音/设备以加速）。
- 中途杀进程，重进后从当前步骤继续。
- 在校日切换后，「今日训练」只显示无琴任务。
